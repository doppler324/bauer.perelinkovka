# Вкладка «Видео в статьях»: маркеры от нейросети и подстановка реальных роликов

Статус: проект, код не пишем. Раздел админки: «Перелинковка внутри текстов» (рядом с «Массовой расстановкой»).

## 1. Идея
Нейросеть, которая пишет статью, сама решает, где нужно видео, и оставляет в этом месте **невидимый маркер** с поисковым запросом. Модуль находит по запросу реальный ролик на выбранной площадке (YouTube, RuTube, VK Видео), выбирает лучший по эмбеддингам и заменяет маркер готовым плеером.

Нейросеть не ищет видео и не выдумывает коды: она отвечает только за **место** и **тему**. Ролик подбирает модуль через API и проверяет, что он существует и встраивается.

## 2. Формат маркера
Маркер не должен быть виден ни в статье, ни в визуальном редакторе. Поэтому запрос лежит в атрибуте пустого `span`:

```html
<span data-bp-video="как поменять масло в двигателе"></span>
```

- Текста внутри нет, на странице ничего не отображается, если модуль не отработал.
- Допустимые необязательные атрибуты: `data-bp-source="rutube"` (принудительная площадка), `data-bp-id` (служебный номер для связи с таблицей расстановок).
- После подстановки маркер заменяется на блок с плеером, а запрос сохраняется в атрибуте для повторной подстановки и отката:

```html
<div class="bp-video" data-bp-video="как поменять масло в двигателе" data-bp-ref="rutube:abc123">
  <iframe src="https://rutube.ru/play/embed/abc123" loading="lazy" allowfullscreen></iframe>
</div>
```

Если подходящего ролика не нашлось, маркер остаётся пустым `span` (ничего не видно) и попадает в список «не найдено» на вкладке.
- Редактор Битрикса (TinyMCE и подобные) может вырезать пустые `span` с неизвестными атрибутами. Нужно проверить на сайте Дениса; запасной вариант: `<span data-bp-video="..." style="display:none"></span>` или комментарий HTML (`<!--bp-video:...-->`; он надёжнее, но не «атрибут span»). Это открытый вопрос.
- Атрибут надо кодировать (`htmlspecialchars`), нейросети запрещаем кавычки внутри запроса.

## 3. Часть промпта для нейросети
Добавляется в промпт генерации статьи. Текст-шаблон хранится в настройках вкладки, где его можно править и копировать в нужный генератор:

```
В статье поставь {N} маркер(а) для видео в местах, где ролик действительно поможет
читателю (инструкция, показ процесса, обзор, пример). Маркер ставь отдельно между абзацами
в таком виде, без изменений:
<span data-bp-video="поисковый запрос из 3–7 слов на русском"></span>
Запрос должен описывать, какое видео нужно, а не повторять заголовок статьи.
Не ставь маркеры подряд, в начале и в конце статьи, внутри списков и таблиц.
Не выдумывай ссылки и коды видео, это сделает система.
```

Значения `{N}`, «в какой части текста» (начало, середина, конец, равномерно) и «1 видео на каждые N знаков» подставляются из настроек вкладки: модуль **собирает пункт промпта по настройкам** и показывает готовый текст. Так настройки Дениса (число видео на статью, на объём текста, часть текста) превращаются в инструкцию для нейросети.

### Контроль после генерации
Нейросеть может ошибиться, поэтому модуль проверяет статью после написания:
- число маркеров больше лимита → лишние удаляются (оставляются лучшие по равномерности);
- маркер внутри списка, таблицы, ссылки, заголовка → переносится после ближайшего абзаца;
- маркеры слишком близко (меньше 2 абзацев) → лишний убирается;
- маркер вне заданной части текста → сдвигается к ближайшей допустимой границе абзаца либо удаляется (по настройке);
- пустой или слишком короткий запрос (меньше 2 слов) → запрос достраивается из заголовка статьи.

## 4. Подстановка: поиск и выбор
Для каждого маркера:
1. **Поиск.** Запрос идёт на выбранные площадки. Берём до 10–20 кандидатов с площадки.
2. **Жёсткие фильтры.** Видео доступно, встраивается, длительность в заданных пределах, язык, нет возрастных ограничений, канал не в чёрном списке.
3. **Эмбеддинги.** Один запрос к OpenRouter считает векторы: запрос маркера и тексты кандидатов (название + начало описания + теги). Дополнительно можно учесть заголовок статьи: итоговая близость = `0.7 × cos(запрос, ролик) + 0.3 × cos(заголовок статьи, ролик)`.
4. **Выбор.** Берём ролик с максимальной оценкой, если она не ниже порога `min_cosine`. Один и тот же ролик не ставится в статью дважды и не больше чем в N статьях.
5. **Подстановка.** Маркер заменяется блоком плеера. Исходный текст статьи сохраняется для отката (как у анкоров).
6. **Нет результата.** Пробуем другую площадку из списка, затем упрощённый запрос (первые 3 слова). Если не нашли, маркер остаётся пустым `span`, строка попадает в «Не найдено».

Это проще, чем общий пул: нет сбора кандидатов «про запас» и расчёта места вставки по абзацам. Кэш остаётся только для результатов поиска по запросу (на несколько суток), чтобы не тратить квоты на одинаковые запросы.

## 5. Площадки

Данные по API и квотам даны по памяти и требуют проверки перед реализацией.

### YouTube — официальный Data API v3
- Ключ: Google Cloud Console, YouTube Data API v3, API key. Бесплатно.
- `search.list` (`type=video`, `videoEmbeddable=true`, `relevanceLanguage=ru`, `safeSearch=strict`) стоит 100 единиц; по умолчанию 10 000 единиц в сутки, то есть около 100 поисков (около 100 маркеров) в день.
- `videos.list` (1 единица на запрос до 50 роликов): длительность, статистика, `status.embeddable`.
- Код: `https://www.youtube.com/embed/ID` (или `youtube-nocookie.com`).
- С сервера из РФ API обычно доступен, но при блокировке нужен прокси. Для посетителей из РФ встроенный YouTube работает плохо — продуктовый риск.

### RuTube — публичный API без ключа
- `GET https://rutube.ru/api/search/video/?query=...`, ключ не нужен. Поля: `id`, `title`, `description`, `duration`, `hits`, `thumbnail_url`, признаки скрытого/недоступного.
- Код: `https://rutube.ru/play/embed/ID`.
- Формат API не гарантирован контрактом: разбор ответа в отдельном адаптере с проверкой полей. Частоту запросов ограничиваем самим (пауза 1–2 сек).
- Для российской аудитории самый надёжный вариант, на старте основной.

### VK Видео — VK API
- `video.search`, нужен токен (скорее всего пользовательский, с правом `video`); токен нужно периодически обновлять. Лимиты VK по частоте запросов.
- Код: `https://vk.com/video_ext.php?oid=...&id=...&hash=...` (hash обязателен для части роликов, приходит в ответе).
- Самый хлопотный, вводим последним.

Источник выбирается чекбоксами, у каждого — приоритет. Порядок обхода при «не нашли» идёт по приоритету.

| | YouTube | RuTube | VK Видео |
|---|---|---|---|
| Ключ | API key | не нужен | токен пользователя |
| Квота | 10 000 ед/сутки, поиск = 100 | не указана | лимиты VK |
| Сервер → API из РФ | обычно да, возможен прокси | да | да |
| Посетитель в РФ | проблемы | да | да |
| Сложность | низкая | низкая | средняя |

## 6. Связь с кодом модуля
- `OpenRouterClient::getEmbeddings()` — эмбеддинги; модель `openai/text-embedding-3-small`. `EmbeddingStrategy` привязан к сущностям инфоблока, поэтому для роликов нужен небольшой класс `VideoScorer`; функцию cosine вынести в общее место.
- В этой ветке настроек прокси нет, а ключ OpenRouter берётся из константы; по памяти проекта ключ и прокси лежат в `options.php` в PR #2. План предполагает, что PR #2 влит и добавлен общий `HttpClient` (curl, прокси, таймауты, ретраи) для OpenRouter и всех площадок.
- Вкладка: `admin/tabs/video_tab.php`, регистрация в `ui.php` (`BP_TEXT_TABS`, `BP_ALL_TABS`, меню), длинные операции порциями через `progress_handler.php` и `progress.js`.
- Обход текста: тот же DOM-обход, что в `AnchorEngine` (абзацы, пропуск `a`, `iframe`, `script`); маркеры находятся по `span[data-bp-video]`.
- Откат: исходный текст хранится по образцу `b_bauer_perelinkovka_anchor`.

## 7. Хранение
Общий пул роликов и векторов больше не нужен. Достаточно двух таблиц.

**`b_bauer_perelinkovka_video_marker`** (одна запись на маркер в статье):
- `ID`, `ELEMENT_ID`, `QUERY`, `STATUS` (found | not_found | applied | rolled_back | manual), `PLATFORM`, `EXT_ID`, `EMBED_URL`, `TITLE`, `SCORE`, `CHECKED_AT`, `UPDATED_AT`.
- Нужна для предпросмотра, повторных прогонов, списка «не найдено», проверки живости, запрета повторов.

**`b_bauer_perelinkovka_video_cache`** (кэш поиска):
- `PLATFORM`, `QUERY_HASH`, `RESULT` (JSON кандидатов с метаданными), `FETCHED_AT`.
- Векторы кандидатов не храним (считаются на лету одним запросом на маркер); хэш текста нужен только при желании кэшировать.

## 8. Интерфейс вкладки (в стиле остальных: `bx-page-title`, `bx-settings-section`, `bx-settings-row`, `bx-btn`, прогресс `progress.js`)
1. **Промпт для нейросети.** Поля: число видео на статью, 1 видео на каждые N знаков, часть текста (начало / середина / конец / равномерно / процент). Ниже готовый текст пункта промпта с кнопкой «Копировать».
2. **Источники.** Площадки, ключи и токены, кнопка «Проверить подключение», приоритет, прокси из настроек модуля.
3. **Подбор.** Порог cosine, вес заголовка статьи, фильтры: язык, длительность, минимум просмотров, чёрный список каналов, «макс. статей на один ролик».
4. **Область.** Инфоблок/раздел статей, режим «только статьи с маркерами».
5. **Кнопки.** «Найти маркеры», «Предпросмотр», «Подставить видео», «Откатить».
6. **Таблица предпросмотра.** Статья, запрос маркера, найденное видео (миниатюра, название, площадка), оценка, статус; действия «другое видео» (список кандидатов), «убрать», «вставить своё видео вручную по ссылке».
7. **Не найдено.** Отдельный список маркеров без ролика с возможностью поправить запрос и повторить.
8. **Проверка живости.** Раз в N дней модуль проверяет подставленные видео; недоступные заменяет следующим кандидатом или возвращает пустой маркер.

## 9. Стоимость
- **Эмбеддинги.** На маркер около 15 текстов × 150 токенов ≈ 2–3 тыс. токенов. Для 4000 статей по 2 видео — порядка 20M токенов ≈ **$0.4**. Это по цене `text-embedding-3-small`, $0.02 за 1M токенов; уточнить по прайсу.
- **YouTube.** 100 единиц на поиск, 10 000 в сутки: около 100 маркеров в сутки. 8000 маркеров — около 80 суток, если искать только на YouTube; поэтому основной источник RuTube (без квот), YouTube — по необходимости или с запросом повышения квоты.
- **RuTube, VK.** Бесплатно, ограничены частотой запросов.
- **Нейросеть-автор.** Пункт промпта добавляет к статье несколько десятков токенов, практически бесплатно.

## 10. Риски
- Нейросеть может не поставить маркер или поставить не там: контроль в разделе 3 и возможность ручной вставки.
- Редактор Битрикса может вырезать пустой `span` с `data-bp-*`: проверить до реализации.
- Запрос нейросети может быть слишком общим: поэтому в оценке участвует заголовок статьи.
- YouTube у посетителей в РФ, авторские права и тематика роликов: порог, предпросмотр перед массовой подстановкой, `safeSearch`, чёрный список каналов.
- iframe тяжёлые: `loading="lazy"`, при желании «лёгкая вставка» (миниатюра и подгрузка плеера по клику).
- Не проверено в живом Битриксе; тестировать на заглушках клиентов площадок.

## 11. Этапы
1. Парсер и контроль маркеров (`span[data-bp-video]`), сборка текста промпта по настройкам.
2. Общий `HttpClient`, `VideoSourceInterface`, адаптеры RuTube и YouTube, кэш поиска.
3. `VideoScorer` (эмбеддинги), выбор ролика, предпросмотр без записи.
4. Подстановка, откат, ручной режим, список «не найдено».
5. VK Видео, проверка живости и агент.
