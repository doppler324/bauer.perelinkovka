# Вкладка «Видео в статьях»: автоматическая расстановка кода видео

Статус: проект, код не пишем. Раздел админки: «Перелинковка внутри текстов» (рядом с «Массовой расстановкой»).

## 1. Что делает вкладка
Для каждой статьи находит на выбранных площадках (YouTube, RuTube, VK Видео) подходящие по смыслу ролики и вставляет в текст код плеера (iframe).
Настройки Дениса: сколько видео на статью, сколько видео на объём текста (например, 1 видео на каждые 3000 знаков), в какой части текста вставлять.
Релевантность оценивается эмбеддингами (cosine между вектором статьи/абзаца и вектором видео).

## 2. Главная идея: поиск и оценка разделены
Поиск по API даёт кандидатов, а решение «подходит или нет» принимают эмбеддинги. Чтобы не тратить квоты и не ходить на площадки при каждой статье, работаем в два этапа:

1. **Сбор кандидатов.** По запросам из статьи (заголовок, ключевые слова, при желании 1–2 фразы из LLM) ищем на площадках, складываем ролики в локальную таблицу вместе с метаданными (название, описание, канал, длительность, просмотры, дата, код встраивания).
2. **Оценка и выбор.** Для кандидатов считаем один вектор на ролик (название + начало описания + теги). Для статьи считаем вектор заголовка и векторы абзацев (как в этапе 1 эмбеддингов анкоров, на лету, без хранения). Выбираем лучшие по правилам из раздела 6.

Один ролик может подходить многим статьям, поэтому кандидаты и векторы хранятся и переиспользуются (пул растёт, повторный поиск нужен редко).

## 3. Площадки

Все данные по квотам и доступности ниже нужно перепроверить перед реализацией (сервисы меняют условия); пункты «проверить» вынесены в открытые вопросы.

### YouTube — официальный Data API v3
- Ключ: Google Cloud Console, проект, включить YouTube Data API v3, создать API key. Бесплатно.
- Поиск: `search.list` (`part=snippet`, `type=video`, `videoEmbeddable=true`, `relevanceLanguage=ru`, `regionCode=RU`, `maxResults=50`). Стоит 100 единиц квоты. Лимит по умолчанию 10 000 единиц в сутки, то есть около 100 поисков в день.
- Детали: `videos.list` (`snippet,contentDetails,statistics,status`) стоит 1 единицу на запрос до 50 роликов. Нужен, чтобы получить длительность, просмотры, теги и проверить `status.embeddable`.
- Код: `<iframe src="https://www.youtube.com/embed/ID" loading="lazy" allowfullscreen>`; для приватности домен `youtube-nocookie.com`.
- Доступность из РФ: запросы к API с сервера обычно идут (Google API не блокируется), но зависит от хостинга, на случай блокировки нужен прокси. Важно другое: у посетителей из РФ YouTube работает плохо (замедление), встроенное видео может не грузиться. Это продуктовый риск, а не технический.
- Вывод: основной «официальный» источник, но использовать осознанно.

### RuTube — публичный API без ключа
- Поиск: `GET https://rutube.ru/api/search/video/?query=...&page=1` (JSON, постранично). Ключ не нужен. Есть Swagger на rutube.ru/api/swagger/ (проверить актуальность). Данные ролика: `id`, `title`, `description`, `duration`, `hits`, `category`, `author`, `thumbnail_url`, `created_ts`, признаки скрытого/недоступного.
- Код: `<iframe src="https://rutube.ru/play/embed/ID" allowfullscreen>`.
- Квоты официально не публикуются; считаем консервативно (пауза 1–2 сек между запросами, кэш, ретраи).
- Доступность из РФ: полная. Для российской аудитории — самый надёжный вариант.
- Риск: API не является строго задокументированным контрактом, формат ответа может измениться. Поэтому разбор ответа в отдельном классе-адаптере с проверками полей.

### VK Видео — VK API
- Метод `video.search` (параметры `q`, `sort`, `adult=0`, `count`, `filters`), нужен токен. В последние годы для видео-методов требуется пользовательский токен с правом `video` (сервисного ключа приложения может не хватать). Проверить на практике.
- Код встраивания: `https://vk.com/video_ext.php?oid=OWNER&id=ID&hash=HASH`. Параметр `hash` приходит в ответе (`player` URL); без него часть роликов не встраивается. Ролики с ограничением доступа/встраивания отсеиваем.
- Квоты: ограничение запросов (порядка 3 запросов в секунду на токен) и суточные ограничения методов. Проверить.
- Доступность из РФ: полная. Риск: пользовательский токен живёт ограниченно, его нужно обновлять; поэтому токен хранится в настройках модуля, а при ошибке авторизации площадка отключается с понятным сообщением на вкладке.
- Вывод: самый хлопотный источник; вводим третьим по очереди, после YouTube и RuTube.

### Сводка

| | YouTube | RuTube | VK Видео |
|---|---|---|---|
| Доступ | официальный API | публичный API | VK API |
| Ключ | API key (бесплатно) | не нужен | токен пользователя |
| Квота | 10 000 ед/сутки, поиск = 100 | не указана | лимиты VK |
| Сервер → API из РФ | обычно да, возможен прокси | да | да |
| Посетитель увидит видео в РФ | с проблемами | да | да |
| Сложность | низкая | низкая (недокументирован) | средняя |

Источник выбирается в настройках чекбоксами (можно несколько). Для каждого источника задаётся приоритет (вес), чтобы при близкой релевантности предпочитался, например, RuTube.

## 4. Связь с уже имеющимся кодом
- `OpenRouterClient` — эмбеддинги через `getEmbeddings()` (модель `openai/text-embedding-3-small`). Для видео используем его же.
- `EmbeddingStrategy` — привязан к сущностям инфоблока; для видео нужен отдельный небольшой класс (`VideoScorer`), но с теми же правилами нормализации и cosine. Общую функцию cosine вынести в одно место.
- Прокси: в текущем коде ветки `claude/project-thread-pxq8wm` настроек прокси нет (`grep proxy` ничего не находит), а ключ OpenRouter в этой ветке берётся из константы `OPENROUTER_API_KEY`. По памяти проекта ключ и прокси лежат в `options.php` в PR #2 с эмбеддингами. Проект видео-вкладки опирается на то, что: (а) PR #2 влит, (б) прокси учитывается общим HTTP-клиентом. Для видео нужен один общий `HttpClient` (curl, прокси, таймауты, ретраи), которым пользуются OpenRouter и все три площадки.
- Админка: вкладка `video` в `admin/tabs/video_tab.php` + `video_settings` (или раздел настроек в самой вкладке), регистрация в `ui.php` (`BP_TEXT_TABS`, `BP_ALL_TABS`, меню). Длинные операции — через `progress_handler.php` и `progress.js` порциями, как массовая расстановка.
- Текст статьи: тот же обход DOM, что в `AnchorEngine` (абзацы, пропуск `a`, `iframe`, `script`).
- Хранение исходного текста до вставки: переиспользуем подход таблицы `b_bauer_perelinkovka_anchor` (оригинал хранится, расстановку можно откатить).

## 5. Хранение

### Таблица кандидатов `b_bauer_perelinkovka_video`
- `ID`
- `PLATFORM` (youtube | rutube | vk)
- `EXT_ID` (id на площадке; для VK `owner_id_video_id`)
- `TITLE`, `DESCRIPTION` (обрезанное до ~1000 знаков), `CHANNEL`, `TAGS`
- `DURATION_SEC`, `VIEWS`, `PUBLISHED_AT`, `LANG`
- `EMBED_URL` (готовый src для iframe, для VK с hash), `THUMB_URL`
- `EMBEDDABLE` (Y/N), `ACTIVE`, `LAST_CHECK_AT` (когда последний раз проверяли доступность)
- `FETCHED_AT`, `QUERY` (по какому запросу найден — для отладки)
- Уникальный ключ `(PLATFORM, EXT_ID)`.

### Векторы `b_bauer_perelinkovka_video_vector`
- `VIDEO_ID`, `MODEL`, `VECTOR` (сжатый BLOB: `pack('f*')`, 1536 float ≈ 6 КБ), `TEXT_HASH` (пересчитывать, только если поменялся текст).
- Отдельная таблица, чтобы смена модели не трогала метаданные.

### Расстановка `b_bauer_perelinkovka_video_placement`
- `ELEMENT_ID`, `VIDEO_ID`, `PARAGRAPH_INDEX`, `SCORE`, `STATUS` (planned | applied | rejected), `IS_MANUAL`, `CREATED_AT`.
- Нужна, чтобы: показывать предпросмотр, не ставить повторно, откатывать, помнить отклонённые ручные варианты.

Объём: на 4000 статей и пул ~10–20 тысяч роликов векторы займут около 60–120 МБ в БД. Допустимо; при росте можно уменьшить размерность (параметр `dimensions` у модели) до 512.

## 6. Алгоритм

### 6.1. Запросы для поиска
Для статьи формируем 1–3 запроса:
1. Заголовок статьи (очищенный от служебных слов).
2. Ключевые слова из свойства `KEYWORDS`, если есть.
3. Опционально (галочка): запрос от LLM (`chat`, дешёвая модель) по заголовку и началу текста: «сформулируй поисковый запрос для видео». Включается отдельно, т.к. стоит денег.

Результаты складываем в пул. Если по запросу уже искали за последние N дней — берём из пула, на площадку не ходим.

### 6.2. Оценка
- Вектор статьи: заголовок + первые абзацы (один запрос эмбеддингов), векторы абзацев — на лету.
- Вектор ролика: `title + " " + первые ~500 знаков описания + теги`.
- Итоговая оценка ролика для статьи: `score = cosine(article, video)`, с небольшими поправками (вес источника, штраф за слишком короткие/длинные ролики, бонус за просмотры лог-шкалой; поправки в сумме не более ±0.05, чтобы не перебивать смысл).
- Порог `min_cosine` (по умолчанию 0.35 для заголовок→ролик; подобрать по предпросмотру, как порог анкоров).
- Дополнительная защита от мусора: ролик должен иметь в названии или описании хотя бы одно слово из ключевых слов статьи (необязательная галочка «требовать общее слово»).

### 6.3. Сколько видео ставить
`count = min(max_per_article, floor(text_length / chars_per_video))`, но не меньше 1, если текст длиннее минимума (настройка «минимальная длина текста для видео»). Пример: лимит 3, 1 видео на 3000 знаков → статья в 5000 знаков получит 1 видео, в 9000 знаков — 3.

### 6.4. Куда вставлять
Настройка «в какой части текста»: варианты
- после первого абзаца (начало);
- в середине;
- в конце (перед последним абзацем);
- равномерно по тексту (для нескольких видео делим текст на `count + 1` частей и ставим на границах);
- процент позиции (0–100% объёма текста) — для тонкой настройки.

Для конкретного места берём **абзац-якорь** — абзац в целевой зоне с максимальным cosine к ролику (внутри зоны допуска ±10–15% объёма). Видео вставляется после этого абзаца. Правила:
- не вставлять внутрь списка, таблицы, цитаты, рядом с другим iframe, сразу после заголовка;
- минимальный промежуток между видео (например, не меньше 2 абзацев);
- не вставлять тот же ролик в статью дважды, и ограничение «один и тот же ролик не более чем в N статьях» (чтобы не было сотни статей с одним видео);
- если в статье уже есть видео (найден iframe/ссылка на площадку) — считается за уже вставленное, по настройке: пропускать статью или докладывать до лимита.

### 6.5. Выбор видео
Жадно: сортируем кандидатов по оценке, берём лучший, ищем для него место, затем следующий, пока не набран `count`. Из почти одинаковых роликов (cosine между собой > 0.9) оставляем один — разнообразие.

### 6.6. Вставка
Оборачиваем в `<div class="bp-video"><iframe ... loading="lazy" allowfullscreen></iframe></div>` с адаптивным соотношением 16:9 через CSS. Исходный текст сохраняется для отката. Маркер `data-bp-video="platform:id"` позволяет находить и удалять свои вставки.

### 6.7. Обслуживание
- Раз в N дней проверять, что ролики живы (`videos.list`, RuTube по id; VK через `video.get`); недоступные помечать `ACTIVE=N`, а в статьях заменять запасным кандидатом или удалять вставку (по настройке).
- Режимы: «предпросмотр» (ничего не пишем), «расставить», «откатить».

## 7. Интерфейс вкладки (в стиле остальных)
Заголовок `<h1 class="bx-page-title">`, блоки `bx-settings-section`, строки `bx-settings-row`, кнопки `bx-btn`, прогресс-бар через `progress.js`.

1. **Источники.** Чекбоксы YouTube / RuTube / VK Видео; рядом статус ключа («ключ задан», «проверить подключение» кнопкой) и вес источника. Ключи YouTube/VK хранятся в `options.php` модуля вместе с остальными ключами.
2. **Сколько видео.** «Макс. видео на статью», «1 видео на каждые N знаков», «Мин. длина текста для видео».
3. **Где вставлять.** Селектор: начало / середина / конец / равномерно / процент, поле допуска, мин. промежуток между видео.
4. **Поиск и релевантность.** Порог cosine, «требовать общее слово», «запрос от LLM», фильтры: язык, минимальная и максимальная длительность, минимум просмотров, «макс. статей на один ролик».
5. **Область.** Инфоблок/раздел статей (как в массовой расстановке), «пропускать статьи с уже вставленными видео».
6. **Кнопки.** «Собрать кандидатов» (с прогрессом), «Посчитать векторы», «Предпросмотр», «Расставить», «Откатить».
7. **Таблица предпросмотра.** Статья, видео (миниатюра и название), площадка, оценка, абзац вставки; у каждой строки: «заменить», «убрать», «ручной выбор видео» (поиск по пулу). Фильтры и сортировка через `tablekit.js`.
8. **Ручной режим.** Поле вставки URL/кода видео вручную для конкретной статьи: ручные вставки приоритетнее и не перезаписываются автоматикой.

## 8. Оценка стоимости
Цены ориентировочные, проверить по актуальным прайсам.

**Эмбеддинги** (`text-embedding-3-small`, $0.02 за 1M токенов):
- пул 15 000 роликов × ~150 токенов ≈ 2.3M токенов ≈ **$0.05**;
- 4000 статей × (заголовок + абзацы, ~1500 токенов) ≈ 6M токенов ≈ **$0.12**;
- повторные прогоны по неизменённому тексту не считаются заново (хэш).
Итого на всё: порядка **$0.2–0.5** разово. Эмбеддинги — не статья расходов.

**Поиск:**
- YouTube: 100 ед. за поиск, 10 000 в сутки по умолчанию → ~100 поисков/сутки. Для 4000 статей при одном запросе на статью — 40 суток без пула. Поэтому: пул и повторное использование, запросы по темам/разделам вместо каждой статьи, либо запрос на повышение квоты. Деньгами бесплатно.
- RuTube, VK: бесплатно, ограничены частотой запросов.

**LLM для запросов** (если включено): дешёвая модель, ~300 токенов на статью → доли цента на статью, для 4000 статей единицы долларов максимум.

Главная «цена» — время сбора кандидатов (квота YouTube, паузы между запросами) и сопровождение (токен VK, формат API RuTube), а не деньги.

## 9. Риски и ограничения
- YouTube в РФ у посетителей: видео может не грузиться.
- Авторские права и соответствие тематике: автоподбор может поставить нерелевантное или неприемлемое видео. Меры: порог, предпросмотр обязательный перед первой массовой расстановкой, фильтры по каналам (чёрный/белый список), `safeSearch=strict` на YouTube и `adult=0` в VK.
- Скорость страниц: iframe тяжёлые → `loading="lazy"`, при желании заглушка-миниатюра с подгрузкой плеера по клику (вариант «лёгкая вставка»).
- Не проверено в живом Битриксе, как и остальные новые функции; тестировать на заглушках клиентов площадок (по аналогии с заглушкой OpenRouter).

## 10. Этапы реализации
1. Общий `HttpClient` (прокси, ретраи) и интерфейс `VideoSourceInterface` с тремя адаптерами; сначала RuTube (без ключа) и YouTube.
2. Таблицы кандидатов, векторов, расстановок; сбор кандидатов с прогрессом.
3. Векторы роликов и оценка, предпросмотр без записи в тексты.
4. Вставка в текст, откат, ручной режим.
5. VK Видео.
6. Обслуживание (проверка живости, замены) и агент.
