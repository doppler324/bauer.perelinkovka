# Блоки перелинковки: правила со своими названиями

## Идея
Блок создаётся в админке (вкладка «Правила») с произвольным названием и символьным кодом (`similar_products`, `accessories`...).
В параметрах компонента (шаблон) выбирается код блока, и компонент выводит только связи этого блока.

## Таблицы модуля
**b_bauer_perelinkovka_block** (правила)
- ID, CODE (уникальный), NAME, ACTIVE, SORT
- SOURCE_IBLOCK_ID, SOURCE_TYPE (element|section)
- TARGET_IBLOCK_IDS (список), TARGET_TYPE (element|section)
- MAX_LINKS (лимит), MIN_SCORE (порог 0..1)
- STRATEGIES (список включённых стратегий)

**b_bauer_perelinkovka_link** (связи) — добавляется поле BLOCK_ID (или BLOCK_CODE).
- Уникальный ключ: (BLOCK_ID, SOURCE_TYPE, SOURCE_ID, TARGET_TYPE, TARGET_ID)
- Поля: SCORE, STRATEGY, IS_MANUAL, ACTIVE, SORT, CREATED_AT, UPDATED_AT
- Ручные связи привязаны к блоку и приоритетнее авто-связей.

## Работа
1. Пересчёт (агент/кнопка) идёт по каждому активному блоку отдельно, применяя его источник, цели, порог, лимит, стратегии.
2. Одна пара может иметь разные связи в разных блоках.
3. Компонент: параметр BLOCK_CODE (выбор из списка блоков), читает только связи этого блока, сортирует: ручные, затем по SORT/SCORE, обрезает по MAX_LINKS блока (можно переопределить в компоненте).

## Админка
Вкладка «Правила»: список блоков, форма блока (название, код, откуда, куда, лимит, порог, стратегии), кнопка «Пересчитать блок». Список связей фильтруется по блоку.

## Порядок внедрения
1. Таблицы блоков и связей с BLOCK_ID.
2. Linker принимает объект правила вместо глобальных настроек.
3. Компонент с параметром BLOCK_CODE.
4. Вкладка «Правила» в админке.
5. Миграция существующих связей в блок «по умолчанию».
